# クライアントのアニメーションに必要な情報：案の比較

検討メモ（2026-11-23）。「おすすめ」の 1（C + D + `endReason`）は実装済み（API 0.11.0）。E は未実装。

## 今の状態で足りないもの

| | 内容 |
|---|---|
| 共通 | `RoomState` に「この state を作った出来事」（誰の手か・時間切れ・投了）が無い。前の state との差分から推測するしかなく、再接続直後や `turn` が飛んだときは推測もできない。試合中は `/log` も読めない |
| frontier | `lastMoves` は戦闘前の命令だけ。エッジ上の衝突・ノードでの戦闘の結果が無い。霧ありでは前の兵数が見えないので逆算もできない。霧ありの `lastMoves` は解決後の見え方で絞るので、奪われて見えなくなったノードへの攻撃や、脱落した人の最後の戦闘が本人に見えない |
| tictactoe | 最後に置いたマスと勝ちの3つ並びが無い（差分・盤面から計算はできるが、再接続直後は最後の一手が分からない） |
| highcard | 足りている（`history` の増加で公開、`hasPlayed` で伏せたことが分かる） |

## 案の比較

| 案 | 中身 | 解決すること | 解決しないこと | コスト（無料枠） | 隠し情報 | 互換性 | 手間 |
|---|---|---|---|---|---|---|---|
| A. `/log` を試合中も開ける | 今の `/log` を `playing` でも返す | 抜けたターンの取り戻し | — | 1回1リクエスト | **漏れる**（`seed` で乱数がすべて分かる、公開前の手が見える）。伏せるにはゲームごとの `redactAction` が要り、霧はそれでも扱いにくい | 追加 | 大 |
| B. `GET /rooms/:id/frames?since=` | 見る人ごとの `view(state_i, pid)` を各ターン分返す（試合中の `/replay`） | 抜けたターンの取り戻し | view に無い出来事（戦闘結果など）は戻らない | 1回1リクエスト。DO が毎回 seed から再生（数百手なら問題なし） | 漏れない（`view` の出力だけ） | 追加 | 中 |
| C. `RoomState.last`（1件） | この state を作った出来事 `{ turn, player, timeout?, resign?, at }` | 誰が・何をしたか（時間切れ・投了を含む）。再接続直後の最初の state にも付く | 手の中身（ゲームごとの view の仕事）。2ターン以上の抜け | 増えない（送信は無料） | 漏れない（今でも `currentPlayers` の減り方で分かる情報） | 追加 | 小 |
| C'. `last` を配列にする | 直近 N 件の出来事 | 数ターンの抜けの「誰が・何を」 | 抜けたターンの中身（view は最新1つだけ。view 側も配列にすると実質 B を state に詰めることになる） | 増えない（state が少し重くなる） | 漏れない | 追加 | 小〜中 |
| D. 出来事をゲームの `S` に持たせて view で見せる | 解決時に結果を `S` に書く（frontier: `lastBattles` を段階順の出来事の列に。tictactoe: `lastCell` / `winLine`） | 手の中身・戦闘の段階ごとのアニメーション。`GET /state` や再接続直後にも入る | 抜けたターン | 増えない | `view` が見る人ごとに伏せる。霧は「関わった人には必ず見せ、他は今見えるノードの分だけ」に直す | view は追加。frontier は `rulesVersion` を上げる（`S` が変わる） | 中（ゲームごと） |
| E. WS 接続時に抜けた分を送る | サブプロトコル `blindfold.since.<turn>` で最後に見た `turn` を伝え、サーバーが抜けた分の `state` を順に送る（上限 50 フレームなど） | 再接続時の抜け（WS 内は順番が保たれるので、抜けは再接続時だけ） | view に無い出来事（D と組み合わせれば戻る） | 増えない（接続は今でも1リクエスト、送信は無料）。DO が再生する CPU のみ | 漏れない（`view` の出力だけ） | 追加 | 中 |

## `last` の形（C の改善）

```ts
last: null | { turn: number; player: string | null; timeout?: string[]; resign?: string; at: number }
```

- `/log` の行から `action` を抜いた形にそろえる（覚えることが増えず、zod の定義も共有できる）。
- `at` があれば、再接続直後に来た古い出来事（`now - at` が大きい）のアニメーションを飛ばせる。
- 試合前・まだ手が無いときは `null`。

## おすすめ

1. **C（`last`）+ D + `endReason` を今やる。** 普段のアニメーションはこれで足りる。どれもフィールドの追加で、無料枠のコストも増えない。
   - D + `endReason` だけでも今のゲームは足りる（下の検討）。ただ、`last` があれば「試合が続く時間切れ」をゲームごとに作らずに済み（frontier の `missed` も、CLAUDE.md の規約も不要）、どの state が何で作られたかを差分から推測しなくてよい。`last` の手間は小さいので入れる。
   - 状態の変化はすべて `commit` → `broadcast` で全接続に配られるので、同じ接続の中では `last` が1件でも抜けは出ない（抜けは再接続時だけ。E の領分）。
2. **E は要望が出てから。** 再接続してもアニメーションを途切れさせたい場合に。B より E のほうがリクエストを使わない。
3. **A と C' はやらない。** A は隠し情報が漏れる。C' は中身が戻らないので得るものが小さい（必要になっても `recent` などの別フィールドとして足せる）。

## D + `endReason` で足りるか（2026-11-23 検討）

`last` が伝えていた「誰が・何をしたか」を、D + `endReason` で置き換えられるかの確認。`onTimeout` / `onResign` を持つのは今は frontier だけ。

| 出来事 | どう分かるか | 足りるか |
|---|---|---|
| 試合を終わらせる時間切れ・投了（tictactoe / highcard は既定でこうなる） | `endReason` と `winners`。既定では負けるのは本人なので `players − winners` で誰か分かる | 足りる |
| frontier の脱落（投了・時間切れの上限） | view の `out`（理由付き） | 足りる |
| 同時手番で誰が出したか | `submitted` / `hasPlayed` の変化 | 足りる |
| frontier の試合が続く時間切れ（`missed < MAX_MISSED`） | `missed` が view に無い。時間切れで入る `[]` は「全ノード待機」と区別できない | **足りない** → 条件 1 で塞ぐ |

足りると言うための条件：

1. **frontier の D に「このラウンドに時間切れした人」を入れる**（ラウンドの出来事として `S` に書くか、`missed` を view に出す）。
2. **規約を CLAUDE.md に足す**：「`onTimeout` / `onResign` を定義していて、それでも試合が続くゲームは、その出来事を `S` に記録して view で見せる」。どのゲームにも付く `last` をやめる以上、これが唯一の保証になる。

`last` をやめると無くなるもの：

- **`at`（古い出来事を飛ばす手段）**：guide に「接続して最初に届く state は今の状態として表示し、アニメーションは同じ接続で続けて届いた state との差分だけにする」と書けば要らない。そのため、D の出来事にはどのラウンドのものかが分かる印を付ける（frontier は `round` で足りる）。frontier は誰かが出すたびに state が届くので、印が無いと同じ戦闘を何度も再生してしまう。
- **どのゲームでも同じ形で「X が時間切れ」と出すこと**：汎用のビューアでは使えない。クライアントはゲームごとに作る前提なので許容する。

`endReason` の置き方：

- 今 WS では、終わった後に接続すると `end` メッセージで理由が届く（`GameRoom.ts` の接続処理）。足すことで変わるのは主に REST の `GET /state` と、理由の置き場所が `RoomState` の1か所にまとまる点。
- `result`（ゲームの `result()` と同じ型）には混ぜない。トップレベルに `endReason: EndReason | null`（finished 以外は null）として置く。出力の enum なので、OpenAPI では `openEnum()` を使う。

あわせて必要な作業：frontier の `rulesVersion` を上げる（`S` が変わるため）。`viewVersion` はフィールドを足すだけなので上げない。`API_VERSION` の minor を上げ、changelog に書く。
